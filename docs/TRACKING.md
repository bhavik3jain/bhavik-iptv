## Decisions made this build

| Decision | Choice | Why |
| --- | --- | --- |
| Package layout | Core · SourceKit · CatalogKit · HouseholdKit · PlayerKit · DownloadKit, plus one package per feature (Home, LiveTV, Library, Profiles, Household, Search, Settings) | Technical spec; separate packages let agents build in parallel without sharing a `.build` |
| Cross-feature navigation | Core's `HearthRoute` + `navigationDestination` in the app; `@Environment(\.play)` with a `PlayIntent` | Features never import each other; the app's playback coordinator owns links, limits, progress |
| Services to views | `CatalogService`, `HouseholdStore`, `ProfileSession` as `@Observable` environment objects | One instance each, value snapshots out |
| Contracts first | Public types and service APIs written before implementation; changes additive only | Lets 6+ agents work at once |
| iPhone Duo | Layout by size class (`\.hearthLayout`), never idiom or orientation; `TabView` sidebar-adaptable; `NavigationSplitView` where regular; no `UIScreen.main`; full-bleed video with controls in the safe area; multiple scenes on | Apple's "Prepare your app for iPhone Duo"; needs Xcode 27.1 / iOS 27.1 SDK for full-screen |
| Orientation | iPhone portrait + landscape (tent mode, player); iPad all four | Duo's outer display honours these; the inner display ignores them |
| Sources in v0.1 | Stalker first and fully; Xtream and M3U clients too, since the protocol work is shared | The owner's provider is a Stalker portal |
| Profiles in v0.1 | Pulled forward from Phase 3: profiles, PIN, Kids, Guest, per-profile favorites/progress | Asked for in this build |
| Mac player | Plays in the main window, not MAC-3's own windows | Owner's choice, 2026-10-28 |
| Search | Asks the provider too, for a source kept only in part | Owner's choice over SRCH-2 ("nothing leaves the device"), 2026-10-28: a page per category can't find most of 162,000 titles |
| Mac and Apple TV signing | Archive unsigned, sign ad hoc, let the App Store export re-sign | Owner's choice: a development profile needs a registered device of that kind |
| Apple TV storage and editing | Stores in Caches; Household read-only; sources arrive through iCloud | tvOS only keeps purgeable data; a remote is no way to type logins |
| Tests | Fixes and features come with regression tests | Owner, 2026-11-01. "Tests later" (2026-10-25) got the app onto TestFlight first; suites for every package followed on 2026-10-26 |
| Titles held across devices | A favorite or progress row carries its title's name, and a device whose catalog lacks the title searches its provider by it | Each device keeps its own catalog, and a Stalker portal asked by id gives only seasons and files, with no name or poster (2026-11-07) |

- **What the portal serves.** Episodes and movies are HLS VOD (`#EXT-X-PLAYLIST-TYPE:VOD`, `#EXT-X-ENDLIST`), one 1080p variant, 15 s target duration, from a CDN that moves between hosts per link. AVPlayer knows the length, the whole title is seekable, and seeks land and play again in 0.3–1.1 s. So scrubbing was the player's fault, not the stream's. The first segment of Grey's Anatomy S23 E2 is 16 MB (2.3 s on this Mac's line); AVPlayer plays nothing until it has it.
- **Slow starts, four causes.**
  - *Resuming* fetched the 16 MB first segment and threw it away: the resume seek went out once the item was ready, which is after that segment. Resumes took 2.4 s, and once 30 s. Seeking the item before it loads started at the resume point in 0.8–1.2 s. `AVPlayerEngine` now does that (`seekBeforeLoading`), with the ready-time seek kept as the fallback. Older AVFoundation threw on a seek before ready, so it's gated to iOS, tvOS and macOS 27, the only runtimes here.
  - *The 6 s start timeout* applied to movies and episodes too. Below about 25 Mbit/s the first segment alone takes longer, so a start that was nearly there was abandoned for a new link and VLCKit, which fetches the same segment again (and then scrubs worse). `PlayerConfiguration.onDemandStartTimeout` (15 s) now covers anything not live on AVPlayer; channels keep 6 s.
  - *The whole guide* (25 MB, `get_epg_info`) was decoded on `StalkerClient`'s actor, and every call's answer is read there too: a `create_link` the portal answered in 0.25 s waited 6.7 s. Answers and the guide's programmes are now read off the actor (`classify`, `bulkProgrammes`, both `@concurrent`). The portal itself answered a link during a slow search and during the guide download in 0.25–0.35 s.
  - *A show's seasons* were asked one after another: Grey's Anatomy's 23 took 5 s, and 27 s in one run, all behind "Loading episodes…". `seriesDetail` now asks four at once (`seasonConcurrency`, as the importer does), keeping the portal's order. With calls overlapping, a call refused on a lapsed session clears the token only if it's still the one it used, so four refusals sign in once rather than ending each other's sessions.
- **Scrubbing.**
  - *The knob snapped back* after every seek while the engine still reported the old time, and quick skips each started from that old time. `PlayerModel.pendingSeek` (`PendingSeek`) holds the target until the engine's clock is within 2 s of it (or 10 s pass), and skips gather for 0.5 s into one seek (`skipGatherDelay`), each press counted from the last target: five presses of +10 are +50 and one segment fetch, not five.
  - *Phone, iPad and Mac:* dragging shows the time under the finger above a larger knob, and the drag follows the finger's movement, slower the further it moves up away from the bar (half, quarter, fine: `ScrubDrag`), so a minute can be found in a two-hour film on a 340-point bar. The bar is 44 points tall to hit.
  - *Apple TV:* left and right on the picture had only ever moved 10 s, so crossing an episode took a hundred presses. A run of presses now grows: 10 s three times, then 30 s, 1, 2 and 5 minutes (`SkipRun`, restarting after 1.5 s or a change of direction), with "+1:30 · 23:41" over the knob and one seek when the presses stop. Channels still skip 10 s. While a stream opens, the centre spinner is now a button, so select from the picture has somewhere to put focus (Next up item 4's spinner).
  - *No bar at all:* the scrub bar and skip buttons need a length. A VOD start that fell back to VLCKit could leave the length unknown when its media didn't report one; `VLCEngine` now keeps the length libvlc reports. Staying on AVPlayer for VOD (above) avoids the fallback in the first place.
